# Cart Take-Over Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.13.0 of Vibe Cartographer with a `/take` command that plans and runs any list or process step, plus an unattended (overnight) mode with local-only branches, park-don't-stop, resume, a decision ledger and a morning report.

**Architecture:** One new shared reference (`skills/guide/references/unattended-run.md`) holds every overnight rule; both `/take` and `/build` cite it instead of duplicating it. `/take` owns intake and planning and writes a run folder, then executes with the existing autonomous engine in `skills/build/SKILL.md`. `/build` gains an unattended branch; its daytime behavior is untouched.

**Tech Stack:** Markdown SKILL and command files, Claude Code plugin manifest, Keep-a-Changelog. No runtime code, no new dependencies. There is no test runner in this repo: each task's "test" is a grep assertion that must fail before the edit and pass after, and Task 7 is the real-app dogfood that is this family's ship bar.

**Spec:** `docs/superpowers/specs/2026-10-16-take-over-design.md` (read it first; this plan argues from it).

## Global Constraints

- Branch: `feat/take-over`. Never commit the pre-existing unstaged changes to root `AGENTS.md` / `CLAUDE.md` (GitNexus rewrite, pending Este's call). Stage files by explicit path, never `git add -A` or `commit -a`.
- No contract-surface changes: builder-profile schema, persona enum, session-log shape, friction shapes, framework pattern numbering, npm package name, marketplace `ref`. Needing one is a stop-and-ask.
- Friction types come only from the canonical seven in `friction-triggers.md`.
- SKILLs name dispatch tiers (`bulk`, `judgment`), never models.
- Version pair moves together: `package.json` and `plugins/vibe-cartographer/.claude-plugin/plugin.json` both to `1.13.0`.
- Voice: no em-dash-heavy prose, no corporate speak, no emoji (repo and global CLAUDE.md rules).
- Unattended defaults copied from the spec: late window `21:00-05:00` local; list-length signal `8+` items; park after the same item's check fails `2` times; run folder `docs/cart-runs/<YYYY-MM-DD>-<slug>/`; integration branch `cart/<run-slug>`; item branches `cart/<run-slug>/<NN>-<item-slug>`; statuses `pending`, `building`, `merged`, `held`, `parked`, `stopped`; stop classes `go`, `hold`, `stop`.

## Review Focus

1. **Dirty working tree at run start.** Expect: the run cuts from the last commit, never stashes or touches the tree, and the morning report notes the uncommitted files. Pinned in Task 1.
2. **Not a git repo, or a repo with no commits.** Expect: `/take` declines unattended mode with one sentence why and offers an attended run. Pinned in Task 3.
3. **Same-day slug collision, or `/take` pointed at an existing run folder.** Expect: an existing non-terminal run folder resumes; a new run with a colliding slug gets `-2`, `-3`. Pinned in Task 1 (resume) and Task 3 (slug).
4. **Ambiguous ask with only one signal** (23:00 with 3 items, or noon with 14 items). Expect: either signal alone makes the confirmation recommend unattended. Neither signal: today's behavior. Pinned in Task 3.
5. **An item discovered mid-run to touch secrets or money.** Expect: upgraded to `stop` or `hold` and recorded as a ledger decision; never downgraded without Este. Pinned in Task 1.
